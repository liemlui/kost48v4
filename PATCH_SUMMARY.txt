WHAT CHANGED
1. CheckoutRequestsModule cleanup
- Removed dead StaysModule import.
- Removed StaysModule from module imports.
- Behavior should not change because CheckoutRequestsService does not inject StaysService.

2. KB-1 renewal invoice auto-ISSUED
- StaysService.renewStay() still creates the renewal invoice as DRAFT temporarily.
- This is intentional because invoice lines must be inserted while invoice is still DRAFT.
- After the renewal rent line is created, the same transaction updates invoice status to ISSUED and sets issuedAt.
- Result returned by renewStay() now contains invoice.status = ISSUED.

3. KB-2 checkout final open invoice guard
- StaysService.complete() now checks blocking invoices inside prisma.$transaction() before updating Stay/Room.
- Blocking invoice definition: status NOT IN [PAID, CANCELLED].
- DRAFT/ISSUED/PARTIAL and any future non-closed status block checkout final.
- Error message is Indonesian and lists invoice number/id + status.

4. Deposit guard alignment
- StaysService.processDeposit() now uses the same open invoice definition before processing deposit.
- Deposit processing is blocked if any invoice is not PAID/CANCELLED.

5. Query open invoice count alignment
- StaysQueryService openInvoiceCount now uses status NOT IN [PAID, CANCELLED].
- This aligns backend list/detail surfaces with KB-2 semantics.
